# ทดลอง PDF → Word (โหมดแก้ไขง่าย)

สคริปต์ทดลองก่อนทำเครื่องมือจริงในเบราว์เซอร์ — รันบน Windows ที่มี Microsoft Word (ใช้วัดผลว่าเปิดใน Word จริงแล้วเหมือนต้นฉบับแค่ไหน)

> ไฟล์ตัวอย่าง (`in/`), ผลลัพธ์ (`out/`, `cmp/`), ฟอนต์ (`fonts/`) และ `venv/` ไม่อยู่ใน git — อาจมีข้อมูลส่วนตัว

## เตรียม

```powershell
python -m venv venv
venv\Scripts\python -m pip install pymupdf pdf2docx
```

- ฟอนต์ OFL สำหรับฝังลง DOCX ไว้ที่ `fonts/` ชื่อ `NotoSansThai-400.ttf`, `NotoSansThai-700.ttf`, `Inter-400.ttf`, … (ดู `embed_fonts.py`)
- `zwsp.mjs` ใช้ fflate จาก `apps/web/node_modules` (รัน `npm install` ใน `apps/web` ก่อน)

## ขั้นตอน

`pipeline.ps1 -Name ชื่อไฟล์ -Tag ชื่อรอบ` (อ่าน `in/ชื่อไฟล์.pdf`) ทำตามลำดับ:

1. `run_patched.py` — pdf2docx + แพตช์ → `thai_fix` → `shape_clips` → ฝังฟอนต์
2. `zwsp.mjs` — ใส่ zero-width space ระหว่างคำไทย (Intl.Segmenter)
3. `roundtrip.ps1` — Word เปิด DOCX แล้ว export เป็น PDF → `score.py` ให้คะแนน
   - **visual**: เทียบหมึกทีละหน้า (ยอมคลาด ±3px) 0–100 — เนื้อหาที่เลื่อนลงทั้งหน้าจะได้คะแนนต่ำแม้หน้าตาเหมือน
   - **text**: ข้อความตรงกันแค่ไหน (ไม่นับช่องว่าง — ลำดับการอ่านที่ต่างก็ถูกหักคะแนน)
   - ภาพเทียบ ต้นฉบับ | ผลลัพธ์ | จุดต่าง อยู่ใน `cmp/`
4. `linecheck.py` — บรรทัดที่ตัดตรงกับต้นฉบับกี่ % (จับกลุ่มตามเส้นฐานแบบหยาบ — ในตารางอาจแยกแถวเกินจริง)

## สิ่งที่พบและวิธีแก้

| ปัญหา | สาเหตุ | แก้ |
|---|---|---|
| ตัวไทยเล็ก/ผิดฟอนต์ | เครื่องไม่มีฟอนต์ → Word แทนด้วย Angsana New | ฝังฟอนต์ OFL ลง DOCX (`embed_fonts.py`) |
| ไทยไม่ใช้ค่าฟอนต์/ขนาดของ complex script | pdf2docx ไม่ใส่ `w:cs` / `w:szCs` / `w:bCs` | `thai_fix.py` |
| คำไทยติดกันหมด | ช่องว่างเป็น span แยก (ฟอนต์ละติน) และ pdf2docx ทิ้ง span ที่เป็นช่องว่างล้วน | แพตช์ `Spans.restore` |
| ย่อหน้ากลายเป็นจัดกึ่งกลาง | ย่อหน้าเต็มบรรทัดมีขอบซ้าย=ขวา → เดาเป็น center | แพตช์ `_parse_alignment` |
| **บรรทัดไทยขาดก่อนเวลา (เนื้อหาเลื่อนทั้งหน้า)** | Word ไม่ได้ตัดคำไทยด้วยพจนานุกรม (ขึ้นกับการตั้งค่าภาษาของ Office แต่ละเครื่อง) จึงตัดได้แค่ตรงช่องว่าง — และตัดข้ามรอยต่อ run ไม่ได้ | รวม run ที่รูปแบบเหมือนกัน + **ใส่ U+200B ระหว่างคำไทย** ด้วย `Intl.Segmenter` (ICU ชุดเดียวกับ Chrome) — คะแนน 53 → 97.5 |
| ระยะบรรทัดไทยไม่ตรง | ระยะแบบ "เท่าของความสูงฟอนต์" ต่างกันในแต่ละโปรแกรม | ย่อหน้าไทยใช้ระยะตายตัว (exact) — ย่อหน้าละตินคงเดิม (เปลี่ยนแล้วกลับเลื่อน) |
| รูปหาย | ภาพลอยทุกภาพ `relativeHeight=0` → ภาพพื้นหลัง (กราฟิกที่ถูกแปลงเป็นภาพ) ทับรูป | `fix_anchor_order`: ภาพใหญ่ชั้นล่าง ภาพเล็กชั้นบน |
| รูปครอปวงกลมกลายเป็นสี่เหลี่ยม | ไม่เก็บ clip path | `shape_clips.py`: clip เป็นเส้นโค้งล้วนตรงขอบรูป → `prstGeom="ellipse"` |
| ตัวอักษรห่าง (letter-spacing) กว้างเกิน + ช่องว่างระหว่างคำหาย | เก็บเป็นช่องว่างแคบคั่นทุกตัว → กลายเป็นช่องว่างเต็มขนาด | แพตช์ `fix_letter_spacing` → `char_spacing` ของ Word |
| ค่าที่ Word ไม่สนใจ | `w:w` และ `w:spacing` เป็นทศนิยม (สเปกต้องเป็นจำนวนเต็ม) | ปัดใน `thai_fix.py` |

**ยังเหลือ:** คำไทยบางคำใน Word กว้างกว่า Chrome −0.3% ถึง +2.6% (shaping ต่างกัน) → บางบรรทัดคำสุดท้ายถูกยกลงไป (ใบสมัครไทย ~4 จุด) · ช่องกรอกในแบบฟอร์มยังเป็นแค่กรอบ ไม่ใช่ช่องกรอกของ Word

**ห้าม:** ให้ Word เปิด PDF เองผ่าน COM (ค้างที่หน้าต่างยืนยันที่มองไม่เห็น)
