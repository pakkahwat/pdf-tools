# ทดลอง PDF → Word (โหมดแก้ไขง่าย)

สคริปต์ทดลองก่อนทำเครื่องมือจริงในเบราว์เซอร์ — รันบน Windows ที่มี Microsoft Word (ใช้วัดผลว่าเปิดใน Word จริงแล้วเหมือนต้นฉบับแค่ไหน)

> ไฟล์ตัวอย่าง (`in/`), ผลลัพธ์ (`out/`, `cmp/`), ฟอนต์ (`fonts/`) และ `venv/` ไม่อยู่ใน git — อาจมีข้อมูลส่วนตัว

## เตรียม

```powershell
python -m venv venv
venv\Scripts\python -m pip install pymupdf pdf2docx
```

ฟอนต์ OFL สำหรับฝังลง DOCX ไว้ที่ `fonts/` ชื่อ `NotoSansThai-400.ttf`, `NotoSansThai-700.ttf`, `Inter-400.ttf`, … (ดู `embed_fonts.py`)

## ขั้นตอน

1. `run_patched.py in.pdf out.docx` — pdf2docx + แพตช์สำหรับไทย → `thai_fix` → ฝังฟอนต์
2. `roundtrip.ps1 -Original in.pdf -Docx out.docx -Label ชื่อ` — Word เปิด DOCX แล้ว export เป็น PDF → `score.py` ให้คะแนน
   - **visual**: เทียบหมึกทีละหน้า (ยอมคลาด ±3px) 0–100 — เนื้อหาที่เลื่อนลงทั้งหน้าจะได้คะแนนต่ำแม้หน้าตาเหมือน
   - **text**: ข้อความตรงกันแค่ไหน (ไม่นับช่องว่าง)
   - ภาพเทียบ ต้นฉบับ | ผลลัพธ์ | จุดต่าง อยู่ใน `cmp/`

## สิ่งที่พบ (25 ต.ค. 2026)

| ปัญหา (ไฟล์ไทยจาก Chrome) | สาเหตุ | แก้ |
|---|---|---|
| ตัวไทยเล็ก/ผิดฟอนต์ | เครื่องไม่มีฟอนต์ → Word แทนด้วย Angsana New | ฝังฟอนต์ OFL ลง DOCX (`embed_fonts.py`) |
| ไทยไม่ใช้ค่าฟอนต์/ขนาดของ complex script | pdf2docx ไม่ใส่ `w:cs` / `w:szCs` / `w:bCs` | `thai_fix.py` |
| คำไทยติดกันหมด | ช่องว่างเป็น span แยก (ฟอนต์ละติน) และ pdf2docx ทิ้ง span ที่เป็นช่องว่างล้วน | แพตช์ `Spans.restore` |
| ย่อหน้ากลายเป็นจัดกึ่งกลาง | ย่อหน้าเต็มบรรทัดมีขอบซ้าย=ขวา → เดาเป็น center | แพตช์ `_parse_alignment` |
| `w:w` เป็นทศนิยม | ไม่ตรงสเปก (ต้องเป็นจำนวนเต็ม) | ปัดใน `thai_fix.py` |

ยังเหลือ: บรรทัดไทยตัดเร็วกว่าต้นฉบับเล็กน้อย (เนื้อหาเลื่อนลง), รูปที่ครอปวงกลมหาย, ระยะบรรทัด
